> Версия набора для технических презентаций разных направлений: пример ниже иллюстрирует схему, а не обязательную тему или язык. Язык и содержание задаются отдельно. Подписи сценария поддерживают русский и английский; для других языков их нужно адаптировать и проверить шрифты и формирование текста. HTML-плеер видео пока содержит русские служебные подписи.

# Общий гайд по техническим презентациям

Этот гайд помогает создавать новые презентации в стиле материалов проекта:
белый фон, спокойная типографика, крупная содержательная графика и связное
объяснение. Тема, число слайдов и длительность выступления задаются отдельно.
Пример по математике показывает применение стиля, но его план не служит
универсальным шаблоном.

## 1. Что хранится в общем наборе

Для академического доклада можно добавить в папку темы `report-title.yaml`:
`university`, `faculty`, `author`, `group`, `city`, `year`. Обе сборки, Word и
LaTeX, используют одни данные титульного листа. Поле `supervisor` необязательно:
без него преподаватель не выводится. Без файла сохраняется титул с заполнителями.

| Файл | Назначение |
|---|---|
| `guideline.yaml` | Единственный источник размеров, цветов, шрифтов и макетов |
| `fonts/` | Резервные шрифты Liberation и лицензия OFL |
| `templates/presentation/deck.yaml` | Рабочий пример содержания и отдельной речи |
| `tools/presentation.py` | Создание папки, сборка, рендер и проверка комплекта |
| `tools/presentation_script.py` | Отдельный PDF выступающего с миниатюрами |
| `tools/presentation_media.py` | Необязательная нативная копия DeckCraft и HTML с видео |
| `tools/deckcheck.py` | Проверка оформления готовых PDF и PPTX |
| `tools/test_*.py`, `tools/selftest.py` | Регрессии и проверка намеренно внесённых дефектов |

Новые презентации используют общие инструменты. В папке темы хранят только
содержание, исходные иллюстрации, данные и результаты. Копирование гайдлайна
и генератора в каждую тему создаёт расходящиеся версии, поэтому его следует
избегать. Новую тему начинают через `presentation.py init`.

## 2. С чего начинается подготовка

До верстки нужны: аудитория и её знания, вопрос выступления, главный тезис,
длительность, источники, формат показа и обязательные ограничения. Используйте
уже известные ответы. Если пользователь просит сразу сделать презентацию,
кратко укажите разумные допущения и продолжайте. Повторное согласование ранее
утверждённого плана не требуется.

План описывает **роль слайда в рассказе**, а не обязательные три пункта.
Для каждого слайда запишите заголовок, вопрос или задачу, показываемый материал,
основной посыл, причину перехода к следующему слайду и примерное время.
Количество пунктов и форма текста определяются содержанием.

Прочитайте заголовки подряд. Они должны позволять восстановить ход объяснения.
Если соседние примеры можно переставить без потери смысла, проверьте, достаточно
ли ясна связь между ними. Переход объясняет, какой вопрос остаётся открытым и
зачем нужен следующий пример.

Возможные линии рассказа:

- Учебное объяснение: вопрос, простая модель, трудность, подходящий приём,
  ограничения и применение.
- Исследование: задача, метод, наблюдение, сравнение с альтернативами,
  границы вывода.
- Выбор решения: критерии, варианты, доказательства различий, компромиссы,
  рекомендация и условия её применимости.

Это варианты построения аргумента. Не добавляйте историю о том, как автор
собирал файлы, если предмет выступления не связан с самим процессом подготовки.
Заключение отвечает на исходный вопрос и опирается на разобранные примеры.
Перед библиографией могут стоять обобщение техник и выводы; их номера зависят
от конкретной презентации.

## 3. Визуальный стиль

Все численные значения ниже объясняют текущий YAML. Изменения вносят в YAML,
а не в текст темы или набор локальных констант.

| Элемент | Правило |
|---|---|
| Холст | 720 × 405 пт, 16:9, белый фон |
| Шрифт | Arial; Courier New для кода, явно на каждом текстовом фрагменте |
| Заголовок | 25 пт, обычное начертание, слева, x = 31,3; y = 46,4 |
| Основной текст | 12 пт, по левому краю, межстрочный интервал 1,3 |
| Акцент | `#3159a6`, короткие смысловые выделения и структурные элементы |
| Выделение | Явно заданный жирный фрагмент того же кегля |
| Номер | «текущий / всего» на каждом слайде, включая титул и источники |
| Таблицы | Редактируемые, тонкая серая сетка, светлый заголовок |
| Эффекты | Без теней, градиентов и декоративных анимаций |

Не выделяйте автоматически начало каждого абзаца. **Определение**, ключевое
ограничение или вывод можно выделить выборочно. Последовательность из одинаковых
троек жирных пунктов превращает объяснение в перечень.

Слайды чередуют связный текст, сравнение, последовательность, таблицу и рисунок.
Одинаковый макет допустим рядом, если он помогает сравнивать результаты в одной
системе координат. Разнообразие служит смыслу, а не становится формальным квотированием.

40–110 слов — ориентир для объясняющего слайда. Для научного рисунка может
потребоваться меньше. Не добавляйте текст для достижения нормы и не уменьшайте
кегль ради плотного абзаца. При переполнении сократите формулировку, измените
компоновку или разделите материал.

## 4. Рисунки и использование пространства

В компоновках с двумя колонками текст стоит слева, рисунок справа. Для квадратной
иллюстрации выбирают `square`, для широкого сравнения под вступлением — `wide`.
Сначала обрезают внешние поля экспорта, затем подбирают размер. Сохраняют
пропорции и обеспечивают не менее 144 dpi в фактическом размещении.

Пустое место между частями одного изображения часто находится **внутри файла**.
Простое увеличение всей картинки этого не исправит. Пересоберите панели с общими
осями, сократите интервалы между ними или экспортируйте отдельно. Растягивание
диаграммы не является способом исправить пустоту.

Подписи осей, единицы, легенды и шкалы остаются внутри рисунка и читаются в размере
слайда. Важные пояснения кодировки и ограничения входят в основной текст.
Отдельных подписей под картинками и служебных подстрочников по умолчанию нет.
Происхождение рисунков и библиография сохраняются в сценарии. Если лицензия или
задача требуют видимой атрибуции, явно согласуйте отступление и сохраните её на слайде.

У каждого изображения есть описание и источник. Для вычисленных результатов
запишите модель, диапазон, параметры, численный метод, проекцию и смысл цвета.
Проверяйте частные случаи и чувствительность к разрешению. Обнаруженный рисунком
узор может подсказать гипотезу, но сам не доказывает утверждение. Эти дополнительные
требования относятся к научным иллюстрациям, а не ко всем темам без исключения.

## 5. Отдельный сценарий выступления

В PPTX и DeckCraft встроенные speaker notes отсутствуют. Сценарий хранится
отдельно и для каждого слайда содержит:

- **Что мы видим**: какие элементы, кривые или панели показаны, что означают
  оси, цвет и маркировка, на какую деталь нужно обратить внимание.
- **Основной посыл**: мысль, которую слушатель должен унести с этого слайда.
- **Речь выступающего**: связное устное объяснение с механизмом, примером,
  чтением изображения и значимыми ограничениями.
- При необходимости действие, паузу, переход, время и ссылки на источники.

Не дублируйте текст слайда целиком и не заполняйте речь фрагментами доклада
автоматически. «Здесь показан график» недостаточно: объясните, какие величины
сравниваются и что позволяет заключить их поведение. Переход должен быть частью
содержательного рассказа.

Общий генератор не обрезает длинную речь: сценарий может занять несколько страниц
на один слайд. Закладки ведут к началу каждого слайда. Сумма заданных интервалов
должна совпадать с длительностью из задания; реальное время проверяется репетицией.

## 6. Видео и интерактивность

Статическая картинка не становится интерактивной от названия. Для выступления
можно показать заранее рассчитанное видео с нужным действием: вращением,
изменением параметра, выбором узла или увеличением. В речи объясните, что меняется
и какие данные пересчитываются. Настоящую интерактивную модель поставляют отдельным
HTML или приложением с инструкцией запуска.

Для каждого ролика нужен MP4, статический кадр той же пропорции и описание.
Рекомендуемый переносимый вариант — H.264, yuv420p, без звука, с faststart.
PPTX содержит сам ролик и получает запуск при входе на слайд. PDF сохраняет кадр
и остаётся статическим. Возможность воспроизведения в предпросмотре не гарантируется.

DeckCraft при импорте PPTX может потерять autoplay. Поэтому создают нативный файл
официальным CLI и повторно проверяют сохранённые параметры и декодирование.
Отдельный HTML с встроенными MP4 работает без сети. Проверка декодера и проверка
хода воспроизведения в запущенном приложении — разные проверки. Перед докладом
нужен показ в том приложении, где он состоится.

## 7. Быстрый старт

Из корня этого набора:

```sh
uv sync --extra presentation
uv run --extra presentation python tools/presentation.py init new-topic
# Отредактируйте new-topic/deck.yaml, добавьте нужные assets/ и data/.
uv run --extra presentation python tools/presentation.py build new-topic/deck.yaml
uv run --extra presentation python tools/presentation.py check new-topic/deck.yaml
```

Получатся `dist/slides.pptx`, `dist/slides.pdf`, `dist/speaker-script.pdf`.
Нумерация и закладки сценария вычисляются по списку `slides`. Генератор
использует общую модель координат, но переносы строк и рендер стороннего
редактора всё равно могут отличаться. Проверьте целевой просмотрщик.

Для нативного DeckCraft и автономного проигрывателя:

```sh
uv run --extra presentation python tools/presentation_media.py new-topic/deck.yaml --cli /path/to/deckcraft-cli
```

Можно задать `DECKCRAFT_CLI` вместо аргумента. В результате появляются
`dist/slides.deckcraft`, а при наличии видео — `dist/animations.html`.
Путь к шрифтам задаётся `DECK_FONT_DIR`. По умолчанию используются локальные
Arial TTF и Courier New TTF из `/System/Library/Fonts/Supplemental`.
Если Arial недоступен и `DECK_FONT_DIR` не задан, используются включённые Liberation Sans и Liberation Mono. Они распространяются с лицензией в `fonts/LICENSE`. Для точного вида Arial предоставьте шрифты отдельно.

## 8. Структура содержания

`deck.yaml` хранит `brief`, `sources` и список `slides`. У каждого слайда
есть стабильный `id`, заголовок, `purpose`, `minutes`, `layout` и `script`.
Поле `transition` требуется для содержательного слайда, после которого есть
следующий. Ссылки в `sources` слайда указывают на ID из общей библиографии.

| layout | Дополнительные поля |
|---|---|
| `cover` | `subtitle`, автор берётся из `brief.author` |
| `prose`, `conclusion` | `body`: список связанных абзацев |
| `compare` | две `columns` с `title` и `body`, необязательный `takeaway` |
| `procedure` | `steps`, до четырёх действий на одном слайде |
| `table` | `table.header`, `table.rows`, положительные относительные `table.widths` |
| `split`, `square`, `wide` | `body`, `image`, необязательный путь `video` |
| `sources` | список ID в `sources`; разбейте длинную библиографию вручную |

Пример с рисунком и видео:

```yaml
id: mechanism
title: Изменение параметра меняет форму
layout: square
purpose: Показать влияние одного параметра при неизменных остальных
minutes: 2
body:
  - Опишите, что меняется и какое свойство помогает увидеть выбранный ракурс.
image:
  path: assets/poster.png
  description: Объяснение осей, цвета, движения и существенных ограничений.
  source: experiment
  trim: false       # для видео кадр сохраняет исходную пропорцию
video: videos/parameter.mp4
sources: [experiment]
transition: Следующий пример проверит, сохраняется ли наблюдение при другом условии.
script:
  see: Подробно опишите показанные панели и обозначения.
  message: Сформулируйте один вывод, поддержанный этим изображением.
  speech: Напишите речь с чтением рисунка и объяснением механизма.
  action: Дайте ролику завершиться, затем укажите на характерное изменение.
```

В реальном файле источник `experiment` должен присутствовать в общей
библиографии с `title`, `location` и `description`. Файлы задаются относительно
папки `deck.yaml`. Поддерживаются растровые изображения; SVG сохраните как
исходник и экспортируйте в PNG нужного разрешения. Сборка откажется принимать
неизвестный макет, пропавший файл, несогласованное время или неподдерживаемый
символ. Для более сложной схемы можно расширить общий генератор; её следует
сохранить редактируемой, если это требуется задачей.

## 9. Что проверяется

Сборка запускает полный `deckcheck` для PDF и PPTX, без пропуска проверок.
Готовность требует **0 ошибок и 0 предупреждений**. Информационные замечания
остаются советами. Сбой проверки считается ошибкой; в строгом режиме предупреждение
также даёт FAIL.

Дополнительно проверяются схема содержания, сумма времени, существование
исходников, свежесть экспорта, число слайдов, соответствие заголовков,
встроенные MP4, условие старта видео, отсутствие заметок и наличие отдельного
сценария. `qa/build-state.json` фиксирует исходники сборки: после изменения темы,
стиля или генератора требуется новая сборка.

```sh
uv run python tools/deckcheck.py new-topic/dist/slides.pptx --strict
uv run python tools/deckcheck.py new-topic/dist/slides.pdf --strict
uv run python tools/selftest.py
uv run --extra presentation python -m unittest discover -s tools -p 'test_*.py'
```

Автоматические проверки не подтверждают точность аргумента, качество рисунка,
правильность научной модели или длительность реальной речи. Просмотрите все
слайды из `qa/slides/`, весь сценарий и проверьте показ в целевом приложении.
Оцените читаемость подписей, пустоту внутри изображений, связь заголовков,
разнообразие уместных форм и обоснованность итогового вывода.

## 10. Дополнительный академический доклад

DOCX и PDF доклада нужны только по заданию. Их оформление задаётся отдельно
в `report` внутри YAML: Times New Roman 12 пт, интервал 1,5, абзац 1,25 см,
Arial для нумерованных заголовков. Требуются нативное поле оглавления,
редактируемые формулы, нумерованные рисунки и таблицы, источники по порядку
первого цитирования. Подписи рисунков доклада сохраняются, даже когда на слайдах
отдельных подписей нет. Сценарий выступления и академический доклад — разные
материалы и могут иметь разный объём.

## 11. Изменение общего набора

Измените YAML с объяснением причины, затем обновите документацию и тесты.
Не ослабляйте проверки ради одной темы. После изменения стиля запишите
его результат, убедитесь, что чистая тестовая презентация проходит, а внесённые
дефекты обнаруживаются. Соберите новый пример через `init` и `build` и посмотрите
результат. Изменения описываются в `GUIDE_CHANGELOG.md`.

Для переноса инструментов на другой компьютер можно собрать отдельный архив:

```sh
uv run python tools/package_style.py
```

Аргумент `--example <папка-собранной-темы>` добавляет её исходный `deck.yaml`
и готовые файлы. Архив содержит общий гайд, стиль, шаблон, проверки, зависимости
без тематических презентаций. Вспомогательные материалы конкретных
докладов, кэши и локальные шрифты в него не входят.
